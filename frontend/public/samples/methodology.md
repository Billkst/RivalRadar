# 竞品分析报告怎么写

> 范文库的"怎么读":先懂方法,再看范例。一份好的竞品分析报告不是功能罗列,而是**有据的决策建议** —— 每个判断都连得到证据,每条结论都经得起"哪里可能错"的追问。本文综合三篇业内方法论,并对齐 RivalRadar 自己的 10 条评分标尺。

## 先定目的与目标

动笔之前先回答一个问题:这份报告是写给谁、解决什么决策的。[woshipm 张在旺](https://www.woshipm.com/evaluating/5672064.html)(《有效竞品分析》作者)把竞品分析的目的归为三类——**决策支持、学习借鉴、市场预警**。三者不是并列堆叠,而是相互排斥的取舍:为"是否进入某市场"做决策支持,需要的是赛道格局与对手定位;为"我们的功能怎么补"做学习借鉴,需要的是逐项功能拆解;为"对手下一步会打哪"做市场预警,需要的是战略动向与时间线。目的错位,后面收集的所有素材都会失焦。

用产品思维写报告,意味着把报告本身当成一个交付的产品来设计:写前先问清三件事——**给谁看**(产品负责人要结论,设计师要交互细节,老板要赛道判断)、**解决什么问题**(补功能、定价格、还是决定要不要做)、**什么场景下用**(评审会上拍板,还是日常竞品监控)。受众和场景决定了报告的形式与详略,而不是反过来用一套模板套所有需求。

最容易踩的坑是闷头做完整版才发现方向跑偏。张在旺给的解药是**一页纸竞品画布**当 MVP:在动手收集数据前,先用一页纸和需求方对齐"选哪几个竞品、比哪些维度、要回答什么问题",拿到确认再展开。这一步看似多余,实则是返工成本最低的保险——把可能耗费一周的分歧,压缩到一次十分钟的对齐里。

## 选对竞品

竞品不是越多越好,而是越准越好。按竞争关系可分三层:**直接竞品**(同样的用户、同样的需求、同样的解决方案)、**间接竞品**(满足同一需求但解法不同)、**潜在竞品**(当下不冲突、但具备跨界进入能力的玩家)。一份决策型报告通常聚焦直接竞品,把间接和潜在竞品作为趋势背景;若是市场预警,潜在竞品反而是重点。

选直接竞品的第一原则是**同定位、同体量优先**。对手太小不构成威胁,太大则不在同一竞争层级,两者都难以给出可比的结论。本库范例 [双雄对决(ref-05)](/samples/ref-05) 选钉钉与企业微信对比,正是因为三者都是"超级移动办公平台"且用户体量相当——同台竞技,差异才有意义;若拿一个百万级 DAU 的平台去比一个万级的工具,得出的任何结论都缺乏说服力。

[飞书《竞品分析报告模板要点》](https://www.feishu.cn/template/competitive-product-analysis-report-key-aspects) 提示,选品时还要明确目标范围,避免把视野局限在"长得像"的产品上。一个实用的定位工具是**价格 × 模式四象限**(Airbnb 早期 BP 用过的方法):横轴铺开高价到低价,纵轴区分商业模式,把候选竞品逐一落点,空白象限往往就是机会所在。这一步既帮你筛掉错误的对标对象,也顺带产出了报告里最有价值的一张定位图。

锚定: 参考 [飞书模板](https://www.feishu.cn/template/competitive-product-analysis-report-key-aspects) · 对应标尺 #1 市场锚定 · 看范例 [双雄对决](/samples/ref-05)

## 定分析维度

维度是报告的骨架。[飞书模板](https://www.feishu.cn/template/competitive-product-analysis-report-key-aspects) 给出了一套通用四方面起点:**产品功能、市场定位、客户反馈、价格策略**。这四类覆盖了"产品好不好、卖给谁、用户怎么说、怎么收费"四个基本面,适合作为任何竞品分析的默认骨架——先把这四列填满,报告就不会缺胳膊少腿。

但通用维度只是起点,真正拉开质量差距的是**结构化的层次深度**。本库范例 [全矩阵横评(ref-06)](/samples/ref-06) 把功能维度细分为战略层、范围层、结构层、框架层、表现层等多层结构,每一层再挂具体子项与证据。从"有这个功能"到"这个功能在产品架构里处于哪一层、服务于什么战略意图",颗粒度的递进直接决定了读者能否据此做判断。

需要警惕的是为深而深。维度服务于第一步定下的目的,不是越多越好:为定价决策做的报告,把功能拆到十层却对计费模式一笔带过,就是把力气用错了地方。判断维度是否合适,只问一句——**少了这一维,核心结论会不会站不住?** 会,就保留;不会,就砍掉。

锚定: 参考 [飞书模板](https://www.feishu.cn/template/competitive-product-analysis-report-key-aspects) · 对应标尺 #3 维度粒度 · 看范例 [全矩阵横评](/samples/ref-06)

## 用分析模型,不止罗列

罗列功能而不给判断,是竞品报告最常见的失败模式——读者看完一页对比表,仍然不知道"所以呢"。[知乎《保姆级写作模板》](https://zhuanlan.zhihu.com/p/668621286) 给出了一套分析模型工具箱,作用就是把零散观察推成可执行结论:**SWOT**(扬长、避短、趋利、避害)梳理自身与对手的相对态势;**波特五力**判断赛道的结构性吸引力;**4P**(产品、价格、渠道、推广)拆解营销组合;**波士顿矩阵(BCG)** 与 **GE 矩阵** 给产品线做取舍;**价值链** 定位优势环节;**市场地图** 看清空白与拥挤。

模型不是装饰,而是推论的脚手架。SWOT 的价值不在于填满四个格子,而在于由格子推出动作:优势对机会,得出"应加大投入"的进攻策略;劣势对威胁,得出"需补短板或回避"的防守策略。同理,波特五力分析完不该停在"竞争激烈",而要落到"因为替代品威胁高,所以差异化是唯一出路"这样的具体判断。

选模型的依据仍是目的:做学习借鉴用 SWOT 加价值链,做市场预警用波特五力加市场地图,做产品线决策用 BCG 加 GE 矩阵。本库范例 [战略评论(ref-08)](/samples/ref-08) 的可贵之处,正是它用模型把功能差异推到了战略层——读者看到的不是"对手有 X 功能",而是"对手用 X 功能卡住了某个生态位,我方若跟进将付出什么代价"。这就是模型与罗列的分水岭。

锚定: 参考 [知乎保姆级模板](https://zhuanlan.zhihu.com/p/668621286) · 对应标尺 #7 战略推论 · #8 Schema 深度 · 看范例 [战略评论](/samples/ref-08)

## 报告结构:总-分-总

报告的整体结构,[woshipm 张在旺](https://www.woshipm.com/evaluating/5672064.html) 推荐经典的**总-分-总**三段式,与飞书的四步流程(确定目标范围 → 收集数据 → 分析解读 → 形成报告)一脉相承——前者是成文的骨架,后者是成文的工序。

**总述**开篇,交代背景、目的、目标、分析思路与目录。这一段是给读者的"导航",让人在三十秒内明白这份报告要回答什么、怎么展开。**分述**是主体,按第三步定下的维度逐项展开,每个维度配一张对比矩阵,并在每维末尾给一句小结——小结不是复述表格,而是从这一维度里提炼出的判断。表格回答"是什么",小结回答"所以怎样"。

**总结**收尾,是全篇最有价值的一段,起的是画龙点睛的作用。它把各维度的分散判断收敛成统一结论,给出可执行建议,并把详细数据、原始素材、参考来源放进附录。很多报告把力气全花在分述的表格上,总结草草几句"综上所述",恰恰浪费了最该用力的地方——读者会反复读的,往往只有这一段。本库范例 [全矩阵横评(ref-06)](/samples/ref-06) 在分述里铺满了对比矩阵和定价模型,但真正让它从"资料汇编"升格为"决策依据"的,是末尾那段把所有格子串成一条结论线的总结。

锚定: 参考 [woshipm 张在旺](https://www.woshipm.com/evaluating/5672064.html) · 对应标尺 #2 对比矩阵 · #5 定价模型 · 看范例 [全矩阵横评](/samples/ref-06)

## 写作铁律

[woshipm 张在旺](https://www.woshipm.com/evaluating/5672064.html) 总结了四条贯穿始终的铁律。**第一,看用户选形式**:给老板的用一页结论加图,给团队的用完整文档加附录,形式服从受众,不存在"标准格式"。**第二,多维度易协作**:维度拆得清晰、命名一致,报告才能多人分工填表、后续迭代复用,而不是变成只有作者本人看得懂的私货。

**第三,可执行、可维护**:结论必须能落到具体动作,且报告结构要支持持续更新——竞品是动态的,一份写完即废的报告价值有限,好的报告应当像一张能反复刷新的看板。**第四,也是最关键的一条——存素材、有来源,绝不编造数据**:每个数字、每条事实都要能追溯到出处;拿不到的数据,就在报告里明确写"暂缺/待补",而不是凭印象填一个看似合理的数字。

这一条正是 RivalRadar 的**反幻觉**底线所在。一份报告的可信度,不取决于它说了多少,而取决于它说的每一句能不能被验证。因此除了不编造数据,还要拒绝套话——"持续关注""加大力度""深入研究"这类话填满了篇幅却给不出任何动作,本质上是用模糊掩盖判断的缺失。本库范例 [批判视角(ref-07)](/samples/ref-07) 的示范在于:它对每个论断都标注了来源,对拿不准的地方明说"证据不足、需进一步验证",反而比那些字字笃定却处处无据的报告更让人信服。

锚定: 参考 [woshipm 张在旺](https://www.woshipm.com/evaluating/5672064.html) · 对应标尺 #4 信息溯源 · #10 反幻觉信号 · 看范例 [批判视角](/samples/ref-07)

## 怎么判断写得好

"写得好"不等于"写得多",更不等于"PPT 做得美"。判断一份竞品报告的好坏,只有两条根本标准:**是否达成了第一步定下的目的,以及结论是否有据可信**。内容堆得再厚、配图再精致,若读者读完仍做不了决策、或核心数字查无出处,这份报告就是失败的。本库的六份范例,正是用六种优秀骨架示范了"达成目的"的不同形态:对决型、全矩阵横评、批判视角、战略评论、框架范式、数据底座——各擅其长,但都做到了有据可信。

为了把"好不好"从主观感受变成可执行的检查,RivalRadar 把上述标准拆成了十条可逐项打分的标尺。它源自对四份权威竞品报告的倒推(详见 `references/README.md`),既是 RivalRadar 自评输出质量的尺子,也可以直接拿来检查你自己写的任何一份竞品报告。

**RivalRadar Rubric v1(10 条 × 0–3 分 = 30 满分)**

| # | 条件 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|---|
| 1 | 市场锚定 | 无 | 提及行业 | 量级数字 / 玩家 | 赛道格局 + 主要玩家定位 |
| 2 | 对比矩阵 | 无 | 表格但 < 3 行 | 3-5 行 / 单维 | ≥ 6 行 / 多维 + 引用 |
| 3 | 维度粒度 | 单层 | 2 层粒度 | 3 层 | 4 层 + 子项有引用 |
| 4 | 信息溯源完整 | 无引用 | 部分引用 | 多数引用 + 部分 broken | 100% 引用 + 0 broken + URL + as_of |
| 5 | 定价模型 | 无 | 列名/价 | 名/价/计费/限额 | 全字段 + 跨竞品对比 |
| 6 | 数据密度 | 模糊形容 | 部分数字 | 多数据点 | 数字 + 来源 + as_of |
| 7 | 战略推论 | 罗列功能 | 单段判断 | 推论链 | 因为 X 所以 Y + 母公司战略映射 |
| 8 | Schema 深度 | 不结构化 | 列表 | SWOT 或对比 | SWOT + 对比 + 用户画像 全 |
| 9 | 时间分层 | 无 | 单层(现状) | 现状 + 未来 | 短/中/长期 + actionable |
| 10 | 反幻觉信号 | 套话满 | 部分 hedging | 多数有据 | 0 套话 + 0 broken refs + 显式 fact/judgment 分层 |

等级:25-30 Excellent(与权威厂商报告同档)/ 20-24 Good(可直接给产品团队决策用)/ 15-19 Adequate / 10-14 Weak / <10 Fail。
